# Upit for Windows

Upit targets **Windows 11 x64**. The consumer installs one `Upit` installer and one product version. The public CLI is available through a stable root launcher; Desktop and the private one-shot File Manager helper remain direct routes into the selected Active Payload, not separate applications.

File Manager Integration uses a per-user Classic Verb under `HKCU\Software\Classes\*\shell\Upit.Upload`. On Windows 11 x64, it appears under File Explorer's **Show more options** (or `Shift+F10`) as `Upload with Upit` and launches the private one-shot helper directly with exactly one selected regular file.

Key lifecycle and architecture properties:

- **Unsigned installation is fully functional**: Ordinary builds generated by `make package` require no code-signing certificate and establish full File Manager Integration. Optional Authenticode signing remains available for protected release tags, but is no longer a functional integration gate.
- **Current-user installation**: `installer.nsi` installs into the current user's local application directory (`$LOCALAPPDATA\Programs\Upit`) without requiring administrator elevation.
- **Stable public CLI**: `%LOCALAPPDATA%\Programs\Upit\upit.exe` forwards to the real CLI in `versions\X.Y.Z`. `HKCU\Software\Upit\PayloadPath` is the sole authority; invalid, missing, staging, recovery, or incoherent payload metadata fails nonzero without scanning another version. Arguments, standard streams, working directory, environment, cancellation, and the CLI exit status are preserved.
- **User PATH ownership**: Installation adds one normalized-equivalent stable-root entry only when absent and broadcasts an environment change. Uninstall removes one entry only when Upit inserted it; a pre-existing equivalent entry is user-owned and survives removal. Unrelated PATH text and order are preserved. Reopen an existing terminal to refresh its environment.
- **Canonical Classic Verb registration**: Registered under `HKCU\Software\Classes\*\shell\Upit.Upload` with `(Default)="Upload with Upit"`, `Icon="<PayloadPath>\upit-desktop.exe",0`, `MultiSelectModel="Single"`, and `command="<PayloadPath>\upit-file-manager.exe" "%1"`. It applies to all regular files (`*`), excludes folders/backgrounds, and suppresses multi-selection.
- **Transactional installation and update**: A new payload is staged before registration switches. The installer verifies the new Classic Verb registration, switches active `PayloadPath` metadata while retaining the previous payload, requests cleanup of any obsolete legacy package (`HungNth.Upit`), and verifies the legacy package is absent. A brief dual-route overlap exists only inside this uncommitted transaction. Successful completion commits one Classic Verb and purges the previous payload; failure compensates back to the previous route (or completely removes partial verb registration and metadata on initial install failure) and retains recovery payload. If state is unknown, the installer retains callable payload and reports cutover failure.
- **Private installer transaction worker**: NSIS extracts the worker outside the payload and stages its uninstaller and shortcut before publication. The worker snapshots product, Classic Verb, and uninstall registry trees plus shortcut and uninstaller bytes. Pre-commit failure restores and re-reads those snapshots; unproven compensation retains recovery material and reports failure. Helpers run from the installation root, not the NSIS plugin directory.
- **Fail-closed uninstall**: The uninstaller removes the Classic Verb and any remaining legacy package registration before deleting product files. If cleanup cannot be proven, the uninstaller aborts and retains payload so users are not left with broken dangling context menu actions.
- **Native Toast clean success**: Windows clean success copies the Final URL, closes progress, and delivers one silent native Windows 11 Toast notification via the Start Menu shortcut AUMID (`HungNth.Upit`) with title `Upload complete` and body `Final URL copied to clipboard.` without opening dialogs or resident apps. Non-clean outcomes (warnings, cancellation, upload/configuration failure, retry) retain full native interactive feedback and recovery actions.
- **Explicit Desktop Repair & passive inspection**: Upit Desktop inspects registration passively without mutating the registry, reading the authoritative active payload path from `HKCU\Software\Upit\PayloadPath` so a stale Desktop cannot retarget an old helper. `Registered` requires the exact verb values pointing to the active helper, existence of that helper binary, and absence of the obsolete legacy package. Damaged/stale verb values or legacy package presence report `Needs Repair`; missing payload reports `Reinstall Upit`. Explicit Repair rewrites the canonical Classic Verb targeting the active payload, cleans legacy package presence, notifies Explorer, and re-inspects. Note that `Registered` reflects structural state and does not structurally guarantee Explorer menu visibility, which can be verified manually in File Explorer (**Show more options**).

## Local packaging and verification

Creating the installer requires **Go** (1.25+), **Node.js/npm**, **NSIS** (`makensis.exe`), and **MinGW resource tooling** (`windres.exe` and its C preprocessor on PATH). Resource generation embeds the requested version and Desktop icon in narrowly staged command packages without changing source files. Visual Studio, CMake, Windows SDK (`makeappx.exe`), and package publisher identities are **not required**; no Explorer C++ adapter is compiled.

Run the unified package command:

```cmd
make package
```

By default `make package` creates an unsigned, fully functional installer at `dist\windows\upit-windows-x64-0.0.0-setup.exe` accompanied by checksum and metadata sidecars:

```cmd
make package VERSION=0.8.0
```

All private binaries and installer payloads use per-run `.build/package/` staging, cleaned on success and failure. `bin/` remains reserved for the standalone native CLI (`upit.exe`). `make clean` removes `bin/`, `.build/`, and repository-root `dist/`, including interrupted package runs.

For protected release builds, set `WINDOWS_CERTIFICATE_PATH`, `WINDOWS_CERTIFICATE_PASSWORD`, `WINDOWS_PROTECTED_TAG=vX.Y.Z`, and `UPIT_PROTECTED_RELEASE=true` in the environment, then run `make package VERSION=X.Y.Z`. `WINDOWS_TIMESTAMP_SERVER` optionally overrides the default timestamp service. This signs the Desktop, real CLI, private helper, stable launcher, private installer worker, and setup installer using Authenticode.

## Consumer installation and removal

Run `*-setup.exe`; no administrator elevation or PowerShell steps are required. Open **Upit** from Start. In Desktop, **File Manager Integration** reports verifiable registry and payload health. **Repair Integration** runs only on explicit user request in the current-user context.

To use File Manager Upload, right-click any regular file in Windows 11 File Explorer, select **Show more options** (or press `Shift+F10`), and click **Upload with Upit**.

To uninstall, remove **Upit** from Windows Installed apps; uninstall removes the Classic Verb and obsolete package registration before deleting product files.

## Protected release

The Windows CI/release workflow uses three gates:

1. Hosted unsigned verification on pull requests and ordinary branch pushes using `bash packaging/command-smoke.sh`, `make package`, and automated install smoke via `packaging/windows/native-smoke.ps1 -AutomatedOnly`.
2. A protected SemVer-tag job that optionally Authenticode-signs executables and the consumer installer using `make package VERSION=$version` with configured signing secrets, verifying signature validity.
3. Dedicated Windows 11 x64 native smoke. The operator verifies the **Show more options** menu surface, selection suppression, progress, cancellation, silent clean success, clipboard recovery without re-upload, Desktop status/Repair, atomic update continuity, Manual Upload, CLI continuity, and fail-closed uninstall. Evidence is captured before publishing the release.

The native release gate requires `UPIT_LEGACY_INSTALLER_PATH` in the protected `upit-windows-native-smoke` environment variables, pointing to a real old packaged setup on that runner. It tests the unsigned artifact and refuses publication unless both operator observations and real package migration are complete. Signing is a separate optional trust check.

## Native smoke

`packaging/windows/native-smoke.ps1` runs on a Windows 11 x64 runner.

### Parameters

- `-InstallerPath <string>` (Mandatory): Path to the consumer `*-setup.exe` installer to test.
- `-InstallDirectory <string>` (Mandatory): Target installation directory (e.g. `"$env:LOCALAPPDATA\Programs\Upit"`).
- `-EvidencePath <string>` (Optional, default `native-smoke-evidence.json`): Destination path for structured JSON smoke evidence.
- `-AutomatedOnly` (Optional switch): Runs unattended automated checks (installation, payload inspection, registry verification, headless-helper invocation, clipboard delivery, CLI continuity, same-version update, and uninstall cleanup) without prompting for operator File Explorer or Desktop observations. Full acceptance is explicitly marked false in this mode because operator-observed UI gates are skipped.
- `-RequireSignature` (Optional switch): Enforces that the tested installer has a valid Authenticode signature. Omitted for unsigned verification smoke.
- `-LegacyInstallerPath <string>` (Optional): Path to a real legacy packaged installer (`v0.6` / `HungNth.Upit`) used to prove legacy migration on actual package identities without mocking.
- `-VerifyLegacyMigration` (Optional switch): Explicitly authorizes migration of an already registered legacy product in the requested test install directory; an existing Classic Verb is still refused.

### Interactive complete-surface run

```powershell
.\packaging\windows\native-smoke.ps1 `
  -InstallerPath dist\windows\upit-windows-x64-0.8.0-setup.exe `
  -InstallDirectory "$env:LOCALAPPDATA\Programs\Upit" `
  -LegacyInstallerPath 'C:\smoke-fixtures\upit-old-packaged-setup.exe' `
  -EvidencePath native-smoke-evidence.json
```

### Automated-only unattended run

```powershell
.\packaging\windows\native-smoke.ps1 `
  -InstallerPath dist\windows\upit-windows-x64-0.8.0-setup.exe `
  -InstallDirectory "$env:LOCALAPPDATA\Programs\Upit" `
  -AutomatedOnly `
  -EvidencePath automated-smoke-evidence.json
```

### What can and cannot be proven

- **Proven by automated smoke**: Current-user silent install, canonical Classic Verb values, required payload presence, headless helper upload and exit, always-copy clipboard delivery, CLI help continuity, same-version update, fail-closed uninstall, and clean registration/payload removal. Headless execution does not prove native progress, Toast absence, or modal-dialog behavior.
- **Proven by operator-observed interactive smoke**: Context-menu placement under **Show more options**, command visibility for exactly one regular file, command suppression for multiple files and directories, invocation through File Explorer, progress display and cancellation, silent clean exit with no modal popups or residual windows, Desktop status (`Registered` vs `Needs Repair`), explicit Repair restoration, and real legacy migration when a legacy package is present.
- **Cannot be proven by supporting smoke alone**: Executing the native smoke script on an individual test machine or automated runner does **not** independently prove SmartScreen reputation across consumer fleets.
- **Actual observed proof vs pending human/old-package prerequisites**: Automated checks record observed factual state. Menu rendering in File Explorer and interactive dialog observations require an operator desktop session; automated UI checks abort safely if a controlled foreground window cannot be acquired. Migration from the legacy MSIX package requires a real prior package installation on the runner (`-LegacyInstallerPath` or pre-existing `HungNth.Upit`), which is verified directly and never fabricated or simulated when absent.

Unsupported release routes: Windows 10 classic shell verbs, Windows ARM64, and portable archive self-registration. macOS uses its own DMG and Finder Services route.
